## Why this is a game

Movement spends time. A shout can burn trust. Choosing how to answer Sevim costs time that Hacer may need. Silent proximity cannot rescue everyone. Burak knows something you do not: he checks the exit and returns to help Sevim without an order. Smoke waves lengthen visibly before closure. You can learn when to cross and choose whom to believe. There is no score or hidden correct dialogue sequence.

## Technology and HF

PixiJS 8 WebGL renders a cut-paper stairwell at 60 fps. TypeScript 7 strict runs one deterministic simulation at 20 Hz on the main thread. HF stays an imported 3.2.0 package. HF owns people, decisions, assent and voice trust. Host code owns positions, fire, visible speech, and offered actions. Inputs enter on a tick and replay without wall time. Iteration 4 versions exports as smoke-3 because resident hazard state and ending semantics change; older exports require their original build and are explicitly rejected by this build. HF settles the preceding minute on the first step, before any rescue can succeed, then ticks on minute boundaries. Route observations enter through HF perception. HF owns trust, need scoring, assent and refusal. The host does not simulate fast arousal; its smoke and caretaker breath are game hazards, not HF physiology. Resident smoke exposure also belongs to the host hazard. Each fixed tick adds the smoke density at the resident’s current floor. A per-seed, per-person tolerance of 850–1200 density-ticks determines when exposure becomes fatal. Outside residents stop accumulating exposure. This is a game rule, not a physiological model. Early evacuation remains possible; later and thicker smoke consumes more of that margin. The existing fast-response request remains with the all director.
